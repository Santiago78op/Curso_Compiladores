Etapa 3 · Parte 1

Recorrer el árbol: semántica y ejecución juntas

La clase Interprete (server/src/interprete/interprete.js) recorre el AST realizando al mismo tiempo la comprobación de tipos (análisis semántico) y la ejecución de las instrucciones — no hay una fase separada de "solo revisar tipos" antes de "ahora sí ejecutar".

La recomendación del enunciado, implementada literalmente

Dos pasadas resuelven la referencia adelantada

El enunciado (sección 5.21) sugiere explícitamente: «se podrán llamar métodos y funciones antes que se encuentren declaradas, para ello se recomienda realizar 2 pasadas del AST generado». Así quedó implementado en Interprete.interpretar():

// PASADA 1: funciones y metodos
for (const g of ast.globales) {
  if (g.tipo === 'FUNCION' || g.tipo === 'METODO') {
    const clave = g.id.toLowerCase();
    if (this.funciones.has(clave)) {
      this.errores.semantico('Ya existe una función o método con el identificador "' + g.id + '"...');
      continue;
    }
    this.funciones.set(clave, g);
    ...
  }
}
// PASADA 2: variables globales y ejecutar
for (const g of ast.globales) {
  if (g.tipo === 'DECLARACION' || g.tipo === 'DECLARACION_VECTOR') this.ejecutarInstruccion(g, this.global);
  else if (g.tipo === 'EJECUTAR') this.ejecutarEjecutar(g);
}

Por qué funciona: en la pasada 1 solo se registra el nodo de cada función/método en un Map — nada se ejecuta todavía. Para cuando la pasada 2 llega a la sentencia ejecutar main();, todas las funciones del archivo ya están disponibles, sin importar en qué orden textual aparecieron. La misma pasada 1 detecta la sobrecarga prohibida: dos funciones con el mismo identificador (case-insensitive) generan error semántico.

Dónde viven las variables

Una cadena de entornos, igual concepto que DataForge

server/src/interprete/entorno.js define la clase Entorno: una tabla (Map) más una referencia a su ámbito padre. Cada bloque anidado (cuerpo de función, ciclo, rama de un if) crea un Entorno nuevo colgado del que lo contiene; buscar un identificador recorre esa cadena hacia arriba hasta el ámbito global.

NivelQuién lo crea
Globalthis.global = new Entorno(null, 'global'), uno por cada Interprete
Función / métodoinvocar(), colgado directamente del global (sin clausura sobre el llamador)
Bloque (if, ciclo, switch)cada execIf/execWhile/execFor/... crea su propio new Entorno(entorno, entorno.nombre)

Claves en minúscula: igual que en DataForge, la tabla normaliza cada clave con .toLowerCase() — el lenguaje es case-insensitive también para identificadores, no solo para palabras reservadas.

Todo dato en tiempo de ejecución sabe su propio tipo

La clase Valor: uniformidad para comprobar tipos

server/src/interprete/valor.js define Valor { tipo, valor, tipoBase, dimension }. Ningún dato circula "pelado" por el intérprete — siempre va envuelto con su tipo (int, double, bool, char, string, null o vector). Los vectores agregan además su tipo base y su dimensión (1 o 2).

Esta uniformidad es lo que permite que operaciones.js compruebe compatibilidad de tipos con una simple consulta a una tabla, en vez de un árbol de if anidados por cada combinación:

// 5.5.6 Modulo -> NOTA: el enunciado define Entero % Entero = DECIMAL
// (identico a la tabla de Raiz). Es inusual (uno esperaria Entero), pero
// se implementa TAL CUAL lo dice la fuente, sin "corregirlo".

Las tablas de + - * / ^ $ % se transcriben literalmente de la sección 5.5 del enunciado como objetos JS (T_SUMA, T_RESTA...); toda combinación no contemplada produce automáticamente un error semántico, sin necesidad de una regla explícita por cada caso inválido.

Dos mecanismos de conversión, deliberadamente separados

Coerción implícita vs. casteo explícito

Coerción (implícita)Cast (explícito, 5.13)
Cuándo se aplicaAl asignar, al pasar un argumento, al retornarSolo cuando el programador escribe cast(expr as tipo)
Conversiones que cubredouble→int (trunca), bool→int/doubleint↔double, int→string/char, double→string, char→int/double
Métodocoercionar(tipoDest, v, l, c)evalCast(nodo, entorno)

Una decisión de diseño queda anotada en el propio código porque, sin ella, el ejemplo oficial del enunciado no compilaría:

/* DECISION DE DISENO: los tipos numericos son mutuamente asignables con
   coercion (double->int trunca). Sin esto, el propio ejemplo oficial
   del Anexo 11.1 seria invalido: `let modulo:int = x % 3` donde `%`
   produce DECIMAL segun la tabla literal del enunciado (5.5.6). */

Es decir: x % 3 da un valor DECIMAL según la tabla 5.5.6, pero el Anexo 11.1 lo asigna a let modulo: int. Sin coerción double→int, ese mismo ejemplo del enunciado sería un error de tipos — la coerción es lo que lo hace válido.

Un error, un solo mensaje — sin cascadas

Propagación por null: el mismo principio que DataForge

Cuando evaluar una expresión produce un error semántico, la función devuelve el null de JavaScript. Toda operación que recibe ese null como operando lo propaga en silencio, sin generar un segundo mensaje de error sobre la misma causa raíz.

Cuidado con la trampa de nombres: el null de JavaScript (señal de "hubo un error antes") es una cosa completamente distinta del valor de tipo 'null' propio del lenguaje .ci — ese es una instancia válida de la clase Valor (Valor.nulo()). Confundirlos rompe la propagación de errores: un Valor de tipo 'null' NO significa que algo falló.

Este es exactamente el mismo principio documentado en la Guía de DataForge — la teoría de manejo de errores semánticos por causa-raíz-única se aplica sin cambios, cambia solo el vehículo (Valor en vez de un tipo primitivo de Java).

Chequeo rápido

Sobre el recorrido del AST

1 · Si main() llama a factorial(), pero factorial está declarada más abajo en el archivo, ¿por qué funciona?

Porque la pasada 1 recorre TODOS los elementos globales y registra cada función/método en el Map this.funciones antes de que la pasada 2 ejecute ninguna instrucción. Para cuando main() realmente corre (durante la pasada 2, disparada por ejecutar main();), factorial ya está en el mapa sin importar su posición textual.

2 · ¿Por qué let modulo: int = x % 3; del Anexo 11.1 no es un error de tipos, si la tabla 5.5.6 dice que el módulo entre enteros da DECIMAL?

Porque la asignación aplica coerción implícita: double→int es una de las conversiones que coercionar() permite (trunca la parte decimal). El valor DECIMAL que produce % se trunca automáticamente al asignarlo a una variable int.

3 · ¿Qué diferencia hay entre el null de JavaScript que usa el intérprete y el valor de tipo null del lenguaje .ci?

El null de JavaScript es una señal interna de "esta expresión ya produjo un error, no reportes otro" — nunca llega al programa .ci. El valor de tipo 'null' del lenguaje es una instancia normal de Valor (Valor.nulo()), tan válida como un int o un string, que el programador puede asignar y comparar deliberadamente.

Etapa 3 · construida

El intérprete recorre, verifica y ejecuta

Dos pasadas resuelven la referencia adelantada, una cadena de entornos resuelve el alcance, una clase Valor uniforme resuelve la comprobación de tipos, y la propagación por null evita cascadas de errores. Falta todavía una pieza central: cómo se implementan break, continue y return sin usar excepciones de JavaScript.
