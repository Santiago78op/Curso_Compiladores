Etapa 1 · Parte 1

Un solo archivo para léxico y sintáctico

Jison es, en el ecosistema JavaScript, el equivalente a Yacc/Bison: un generador de analizadores LALR(1). A diferencia de JFlex+CUP, Jison reúne la especificación léxica y la sintáctica en un único archivo: server/src/grammar.jison.

El archivo tiene dos mitades separadas por %%: primero %lex … /lex (los tokens), después la gramática de producciones.

Lo primero que resuelve el archivo

Una directiva resuelve la sección 5.1 completa

/* server/src/grammar.jison, línea 10 */
%lex
%options case-insensitive flex

%%

%options case-insensitive hace que cada patrón literal se compare ignorando mayúsculas/minúsculas, sin tener que escribir [lL][eE][tT] a mano para cada palabra reservada — algo que sí hacía falta enunciar explícitamente en JFlex con %ignorecase, pero aquí es una sola línea que cubre reservadas e identificadores por igual.

Verificado contra el enunciado (5.1): let a:int = 10; y LeT A: iNt = 0; son la misma instrucción. El lexema original no se conserva porque el lenguaje no distingue mayúsculas en ningún reporte — a diferencia de DataForge, donde si importaba para los reportes.

Una decisión propia del proyecto (no exigida literalmente, pero necesaria para 5.4): las secuencias de escape (\n \t \" \' \\) se traducen a su carácter real dentro de la propia regla léxica, con .replace(), antes de devolver el token — el intérprete nunca ve la barra invertida cruda:

\"(\\.|[^\\"])*\"    %{
                       yytext = yytext.slice(1, -1).replace(/\\(.)/g, function (m, c) {
                         switch (c) { case 'n': return '\n'; case 't': return '\t';
                           case '"': return '"'; case "'": return "'"; case '\\': return '\\';
                           default: return c; }
                       });
                       return 'CADENA';
                    %}

Manejo de errores, primera capa

El carácter desconocido no detiene el análisis

La última regla del bloque %lex es un catch-all (.) que coincide con cualquier carácter que no calzó con ninguna regla anterior. En vez de fallar, empuja un error al arreglo compartido yy.errores y continúa — igual que el modo de recuperación léxica de DataForge (descartar y seguir).

/* Recuperacion de error lexico: descarta el caracter y sigue (seccion 6.1) */
.                                   %{
                                       if (yy.errores) {
                                         yy.errores.push({ tipo: 'Léxico',
                                           descripcion: 'El carácter "' + yytext + '" no pertenece al lenguaje',
                                           linea: yylloc.first_line, columna: yylloc.first_column + 1 });
                                       }
                                    %}

El objeto yy es la clave: Jison comparte una única variable yy entre el lexer generado y las acciones sintácticas. Eso permite que el léxico reporte errores directamente en la lista que después usa todo el resto del pipeline, sin inventar un canal de comunicación aparte. Se profundiza en la Etapa 2.

Chequeo rápido

Sobre el léxico de .ci

1 · ¿Qué pasaría si la regla de ID se moviera antes que las palabras reservadas en grammar.jison?

Ninguna palabra reservada se reconocería jamás: a igual longitud de coincidencia, Jison prefiere la regla escrita primero, exactamente igual que JFlex. if, let, function, etc. pasarían a ser identificadores comunes.

2 · ¿Por qué los escapes de cadenas se resuelven en la regla léxica y no más adelante, en el intérprete?

Porque el escape es un fenómeno puramente léxico: transformar \n en un salto de línea real no depende de ningún contexto sintáctico ni semántico. Resolverlo ahí evita que cada consumidor posterior del valor de la cadena (el intérprete, los reportes) tenga que repetir la misma lógica de reemplazo.

3 · ¿Qué gana el proyecto al compartir el objeto yy entre el lexer y el parser, en vez de que cada uno maneje sus propios errores por separado?

Un único arreglo de errores acumula tanto los léxicos como los sintácticos (y luego también los semánticos, que agrega el intérprete), en el orden en que ocurrieron. El reporte final (Etapa 5 y 6) puede ordenarlos por línea/columna sin tener que fusionar fuentes distintas.
