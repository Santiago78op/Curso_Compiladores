La construcción de un intérprete

DataForge: un programa en Java que lee código escrito en un lenguaje inventado (.df), lo entiende y lo ejecuta — calcula, imprime y grafica.

Etapa 0 — antes de tocar código: los tres conceptos que sostienen todo el proyecto.
Hay que navegar con las flechas del teclado ← → o los botones de abajo.

El problema de fondo

Para Java, el código es solo una tira de caracteres

El usuario escribe un archivo .df. Pero Java no sabe leer DataForge: lo que recibe es esto — un carácter tras otro, sin significado:

v a r : d o u b l e : :   n u m e r o   < -   2 . 5   e n d ;

El proyecto es el proceso que convierte esa tira de caracteres en una acción: "declarar una variable llamada numero con el valor 2.5".

Un programa que lee código fuente y lo ejecuta directamente se llama intérprete. Los 4 proyectos del curso son intérpretes.

La analogía clave

Esto ya se sabe hacer: ocurre al leer

Cuando se lee «El gato negro duerme.», el cerebro hace tres cosas sin que se note:

1

Agrupa letras en palabras

No se lee E-l-g-a-t-o. Se lee «El», «gato», «negro», «duerme» — y se clasifica: sustantivo, adjetivo, verbo.

2

Verifica el orden

«El gato negro duerme» ✓ suena bien. «Gato el duerme negro» ✗ — mismas palabras, orden inválido.

3

Entiende y reacciona

Se imagina al gato durmiendo. El significado produce un efecto.

Un intérprete hace exactamente esas tres cosas con el código fuente. Solo cambian los nombres.

Concepto nº 1

¿Qué es un token?

Un token es una «palabra» del lenguaje de programación, ya clasificada. La unidad mínima con significado.

Igual que en español las palabras tienen categorías (sustantivo, verbo, adjetivo), en DataForge las «palabras» tienen categorías:

CategoríaQué esEjemplos en DataForge
Palabra reservadaPalabra fija del idioma: siempre significa lo mismovar, double, end, SUM, PROGRAM
IdentificadorNombre propio inventado por el usuarionumero, edad, copia
Literal numéricoUn valor concreto2.5, 0, 57.75
Literal de cadenaTexto entre comillas"hola", "Enteros"
SímboloSignos de puntuación y operadores:, ::, <-, ;, (, )

Anatomía de una línea real

Conviene pasar el mouse por cada pieza

Esta línea sale del enunciado (sección 5.5). Así la parte y clasifica el analizador léxico:

var:double:: numero <- 2.5 end;
  • palabra reservada
  • identificador
  • número
  • símbolo

Nueve caracteres… no: nueve tokens. La línea completa significa: «declará una variable de tipo decimal, llamada numero, con el valor 2.5» — pero ese significado lo arma la capa sintáctica. El léxico solo corta y clasifica.

Concepto nº 2 — la única sutileza de hoy

Token · Lexema · Patrón

var es siempre el mismo texto: con verlo, ya está. Pero numero y 2.5 cambian en cada programa (edad, x, 3.14, 100…). Para esos, el analizador no memoriza textos: memoriza una regla de forma.

Token

La categoría.
Ej.: «identificador», «número».

Lexema

El texto concreto que apareció.
Ej.: numero, 2.5, edad.

Patrón

La regla de forma que los reconoce.
Ej.: «letras seguidas de letras o dígitos».

"hola", "adios" y "Enteros" son tres lexemas distintos del mismo token (cadena), reconocidos por un solo patrón: «cualquier cosa entre comillas dobles».

Fuente: Dragón §3.1 · nota del vault: Token, lexema y patrón.

¿Y esto para qué?

JFlex es, literalmente, una lista de patrones

La herramienta del proyecto (JFlex) funciona así: se le escribe una lista de reglas «cuando se vea esto → se entrega este token», y ella genera automáticamente el código Java que corta y clasifica cualquier archivo .df.

// idea (todavía no es sintaxis real de JFlex):
"var"                        → token VAR
"double"                     → token DOUBLE
"<-"                         → token ASIGNACION
letra (letra|dígito)*        → token ID
dígitos ("." dígitos)?       → token NUM_DOUBLE
"texto entre comillas"       → token CADENA

Por eso la primera pieza real del proyecto será la tabla de tokens: recorrer el enunciado completo y extraer todo el vocabulario del lenguaje con su categoría y su patrón. Esa tabla se traduce casi 1 a 1 al archivo .flex.

Chequeo rápido

¿Quedó claro? Momento de comprobarlo

Conviene pensar la respuesta antes de revelar. Si se falla alguna, hay que volver dos diapositivas.

1 · En var:char[]::cadena <- "hola" end; — ¿cadena es palabra reservada o identificador?

Identificador. Es un nombre que inventó el usuario para su variable — pudo llamarse saludo o x. Que su texto «cadena» suene a concepto del lenguaje no importa: no está en la lista de palabras fijas de DataForge.

2 · "hola" y "adios" son lexemas diferentes… ¿del mismo token o de tokens diferentes?

Del mismo token (cadena). Un solo patrón — «lo que sea entre comillas dobles» — reconoce infinitos lexemas posibles. Token = categoría; lexema = el texto concreto de cada aparición.

3 · Bonus: que VAR y var valgan lo mismo (el lenguaje es case insensitive) — ¿en qué capa se resuelve?

En la léxica. Es un problema de reconocer la palabra, no del orden de la frase. El patrón de JFlex aceptará mayúsculas y minúsculas. Lo vemos en la Etapa 1.
