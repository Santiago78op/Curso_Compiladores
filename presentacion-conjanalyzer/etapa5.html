Etapa 5 · Parte 1

El diagrama de Venn (sección 5.1)

El enunciado pide visualizar, para cada operación, qué región del universo abarca su resultado. La solución de ConjAnalyzer no dibuja formas aproximadas: calcula, píxel por píxel, si cada punto pertenece de verdad al resultado.

Clase: gui/DiagramaVenn.java. Reutiliza directamente NodoOperacion.pertenenciaRegion de la Etapa 3.

La idea central

Sombreado exacto, no aproximado

Un diagrama de Venn "de libro" dibuja regiones a mano según qué operación se quiere ilustrar. Acá se invierte el proceso: por cada píxel del Canvas, se calcula en qué círculos (conjuntos base) cae, y se evalúa la operación como función booleana sobre esa combinación — si da true, el píxel se pinta.

for (int y = 0; y < ALTO; y++) {
    for (int x = 0; x < ANCHO; x++) {
        boolean dentroDeAlguno = false;
        for (int i = 0; i < n; i++) {
            double dx = x - centros[i][0], dy = y - centros[i][1];
            boolean adentro = dx*dx + dy*dy <= r*r;      // ¿dentro del circulo i?
            region.put(bases.get(i), adentro);
            dentroDeAlguno |= adentro;
        }
        if (op.arbol.pertenenciaRegion(region)) {          // Etapa 3
            pw.setColor(x, y, dentroDeAlguno ? DENTRO : FUERA);
        }
    }
}

Por qué esto es exacto y no una aproximación visual: pertenenciaRegion es la MISMA función que calcula la pertenencia real de un elemento a la operación (Etapa 3) — no hay una lógica de dibujo separada de la lógica de evaluación. Si el árbol cambia (por ejemplo, después de simplificarse), el dibujo sigue siendo correcto sin tocar una línea de DiagramaVenn.

Geometría

De 1 a 3 círculos — y el límite honesto

Conjuntos baseDisposición
1un círculo centrado
2dos círculos superpuestos, uno junto al otro
3trébol clásico: dos arriba, uno abajo al centro
4 o mássin Venn geométrico razonable — se muestra el resultado solo en texto

op.referencias (método de NodoOperacion, Etapa 3) es lo que le dice al diagrama cuántos conjuntos base tiene que dibujar y cómo etiquetarlos. Con más de 3, dibujar círculos que representen honestamente todas las combinaciones de pertenencia ya no es geométricamente posible con circunferencias simples — de ahí la decisión documentada de degradar a texto.

El caso especial: el complemento

Sombrear también "lo que queda fuera de todos los círculos"

El complemento de un conjunto incluye elementos del universo que no pertenecen a ningún conjunto base dibujado. Por eso DiagramaVenn usa dos tonos del mismo color: uno para "dentro de algún círculo" (DENTRO) y otro más claro para "fuera de todos" (FUERA) — ambos activados por el mismo if (op.arbol.pertenenciaRegion(region)), solo cambia qué tono se usa según dentroDeAlguno.

Esto es una consecuencia directa de cómo funciona pertenenciaRegion sobre un nodo unario: return !izq.pertenenciaRegion(region). Para un píxel que no cae en NINGÚN círculo, todas las entradas del mapa region son false — y aun así el complemento de eso puede evaluar true.

El panel de una operación

Título, canvas, expresión, resultado y simplificación — todo junto

DiagramaVenn.crear(Operacion op) arma un VBox con 5 piezas: el nombre de la operación, el Canvas sombreado, la expresión en notación prefija (op.arbol.toPrefijo()), el resultado evaluado y — si aplica — la simplificación con sus leyes:

String simplTxt = op.simplificacion.seSimplifico
        ? op.simplificacion.simplificado.toPrefijo()
          + "   [leyes: " + String.join(", ", op.simplificacion.leyes) + "]"
        : "No se puede simplificar la operacion";

Un panel por operación, navegable con ◀/▶/ComboBox desde EditorApp — el mismo criterio de "navegación entre gráficos generados en la ejecución" que pide la sección 5.1 del enunciado.

Chequeo rápido

¿Se entiende el sombreado por función booleana?

1 · Para una operación con 5 conjuntos base referenciados, ¿qué muestra el panel de Venn?

Solo texto: "Venn no disponible para 5 conjuntos base". No existe una disposición geométrica razonable con círculos simples para más de 3 conjuntos, y el proyecto lo reconoce en vez de dibujar algo engañoso.

2 · ¿Por qué el sombreado NO necesita recorrer el Set<Character> completo del universo?

Porque en vez de preguntar "¿qué caracteres pertenecen al resultado?", se pregunta "¿este PUNTO del canvas (que representa una combinación hipotética de pertenencias) satisface la función booleana de la operación?" — pertenenciaRegion resuelve eso sin necesidad de conocer ningún carácter concreto.

3 · Si Simplificador reescribe el árbol de una operación, ¿hay que cambiar algo en DiagramaVenn para que el dibujo siga siendo correcto?

No. El diagrama usa op.arbol (el árbol ORIGINAL evaluado, no el simplificado) para el sombreado, así que es independiente de la simplificación — el panel solo MUESTRA el árbol simplificado como texto informativo aparte, sin usarlo para dibujar.
