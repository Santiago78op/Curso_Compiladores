Etapa 7 · Parte 1

Un cliente que ya existía, adaptado a un backend nuevo

El cliente web de VLangCherry (React 19 + Vite) reutiliza y adapta el patrón de interfaz de CompInterpreter — mismo contrato {errores, consola, simbolos, ast} — reemplazando únicamente la capa de comunicación para apuntar al servidor Go (Etapa 6) en vez de a un servidor Node/Express.

Qué se reusa y qué se reemplaza

Mismo contrato, backend distinto

El cliente de VLangCherry adapta el patrón de interfaz de otro proyecto del curso con arquitectura cliente-servidor equivalente. La UI (componentes, estado, interacción) se reusa casi sin cambios; lo único que cambia es la capa de comunicación:

CompInterpreter (OLC1)VLangCherry (OLC2)
BackendNode.js + ExpressGo + net/http
Contrato JSON{errores, consola, simbolos, ast}El mismo, más consolaLineas y dot
Grafo de AST en clientevis-networkvis-network (idéntico)
FrontendReactReact 19 + Vite

AstGrafo.jsx reutiliza variables CSS del tema activo (claro/oscuro) para los colores de nodo, borde y texto — consistente con el resto de la interfaz.

Chequeo rápido

Sobre el cliente

1 · ¿Qué archivo hay que tocar si el servidor Go cambia de puerto o de dominio?

api.js (vía la variable de entorno VITE_API_URL) — es el único punto que conoce la URL del backend. El resto de los componentes solo conocen la forma del JSON de respuesta.

2 · ¿Por qué CORS está habilitado con * en todas las rutas del servidor?

Porque en desarrollo el cliente (Vite, otro puerto) y el servidor (Go, net/http) corren en orígenes distintos; sin encabezados CORS, el navegador bloquearía el fetch de api.js a /interpretar.

3 · Si se agrega un campo nuevo al AST y aparece en el JSON de /interpretar, ¿hace falta cambiar AstGrafo.jsx?

No, mientras el formato siga siendo {nodes, edges} — el recorrido por reflection del servidor (Etapa 2) ya incorpora el nuevo campo al grafo automáticamente, y vis-network solo necesita ese mismo formato genérico para dibujarlo.
